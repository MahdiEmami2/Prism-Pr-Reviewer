
**6. Why this matters**

A default value that is a list, dict, or set literal is created once at function definition time and shared across every call. Mutating it inside the function leaks state between calls, which is a documented language behaviour, not a style preference.

**7. Suggested remediation**

Use None as the default and build the container inside the body.

**8. Recommended tests**

Call the function twice and assert the second call is unaffected.

## 9. Analysis limitations

- Static analysis only: PRISM never imports, compiles or executes analysed code, so it cannot prove runtime behaviour.
- A finding describes what the diff contains, not what the program does when it runs.
- Findings are limited to changed lines. Pre-existing problems on unchanged lines are out of scope for a pull-request review.
- Rules in the 'heuristic' class are review prompts derived from patterns. They have a measurable false-positive rate and are never presented as proof.
- 2 file(s) use a language PRISM has no deterministic rules for; only credential patterns were applied to them.
- 2 file(s) were skipped; the scope section lists each reason.
- No coverage report was supplied, so no statement about test coverage is made.

Coverage data: no coverage report was supplied, so no coverage statement is made.

PRISM reports findings and does not post them anywhere. Generating a report and publishing a review comment are separate operations, and this build performs no publishing.
